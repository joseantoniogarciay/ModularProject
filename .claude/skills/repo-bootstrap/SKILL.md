# Repository bootstrap

This project depends on three layers that must be installed and resolved in order. Each layer pins the next. Skipping any of them breaks the build.

```
mise (tool version manager)        ← installed via Homebrew
  └── tuist                        ← version pinned in .mise.toml
        └── SwiftLint + future SPM ← versions pinned in Tuist/Package.resolved
              └── External SPM xcframeworks ← built by `tuist cache --cache-profile only-external`
                    └── ModularProject.xcworkspace  ← regenerated by `tuist generate`
```

## Required outcome

After running this bootstrap, the user must be able to:

1. Open `ModularProject.xcworkspace` in Xcode and build.
2. Run `xcodebuild -workspace ModularProject.xcworkspace -scheme App -destination 'generic/platform=iOS Simulator' build` and see `** BUILD SUCCEEDED **` with SwiftLint running as a pre-build script on every target.

If either fails, the bootstrap is incomplete.

## Procedure

Run from the repository root. Each step is idempotent — if the artifact already exists at the required version, the step is a no-op.

### 1. mise (tool version manager)

```bash
which mise || brew install mise
```

If freshly installed, ensure shell activation is in place. For zsh:

```bash
grep -q 'mise activate zsh' ~/.zshrc || echo 'eval "$(mise activate zsh)"' >> ~/.zshrc
```

Then **open a new terminal** (or `source ~/.zshrc`) so `mise activate` is loaded. From any subdirectory of this repo, `which mise` should resolve, and `mise current` should list the tools declared in `.mise.toml`.

mise treats config files as untrusted by default. Run once per machine:

```bash
mise trust
```

### 2. Pinned tool versions

```bash
mise install
```

This reads `.mise.toml` and installs the declared version of each tool (currently only Tuist `4.195.1`). After this, `mise which tuist` should point to `~/.local/share/mise/installs/tuist/<version>/tuist`, **not** to `/opt/homebrew/bin/tuist`.

Verify:

```bash
tuist version    # must match the version in .mise.toml
```

If it does not match, mise activation is not loaded — return to step 1.

### 3. SPM dependencies

```bash
tuist install
```

Fetches the dependencies declared in `Tuist/Package.swift` (today: SwiftLint) into `Tuist/.build/`. The exact versions are locked in `Tuist/Package.resolved`, which is committed.

Verify the SwiftLint binary exists at the deterministic path:

```bash
ls Tuist/.build/artifacts/swiftlint/SwiftLintBinary/SwiftLintBinary.artifactbundle/macos/swiftlint
```

This path is referenced by the SwiftLint Run Script that every target carries. If it is missing, every build will print a warning but will not fail.

### 4. Cache external SPM dependencies as xcframeworks

```bash
tuist cache --cache-profile only-external
```

Compiles every SPM dependency declared in `Tuist/Package.swift` (Alamofire, Kingfisher, Pulse, PulseUI…) into `.xcframework` binaries stored under `~/.cache/tuist/`. The next `tuist generate` references those binaries instead of integrating the SPM source as Xcode targets, so Xcode never recompiles Alamofire/Kingfisher/Pulse on `clean` builds.

First invocation on a clean machine takes 30-60s+ (it actually compiles the deps). Subsequent invocations are near-instant: Tuist hashes the dependency graph and skips anything already cached. Idempotent in the same sense as `tuist install`.

Only own modules (Core, Networking, SharedUI, Data, Features, App) stay as source targets — never cache those during local development unless you adopt the focused-generation workflow (`tuist generate <TargetName>`), which is out of scope here.

### 5. Generate the Xcode workspace

```bash
tuist generate --no-open
```

Produces `ModularProject.xcworkspace` and the per-module `.xcodeproj` files. These are **not** committed (gitignored) — they must be regenerated on every clone and after any change to `Project.swift`, `Workspace.swift`, or `Tuist/ProjectDescriptionHelpers/`. The output should list `Using cache binaries for the following targets:` followed by the SPM names if step 4 ran successfully.

### 6. Smoke test

```bash
xcodebuild -workspace ModularProject.xcworkspace \
  -scheme App \
  -destination 'generic/platform=iOS Simulator' \
  -configuration Debug build
```

Expected: `** BUILD SUCCEEDED **`. If SwiftLint emits violations they appear as Xcode warnings/errors; the build still succeeds for warnings.

## When to re-run which step

| Trigger | Re-run from step |
|---|---|
| Fresh clone | 1 |
| `.mise.toml` changed (Tuist version bump, new tool) | 2 |
| `Tuist/Package.swift` or `Tuist/Package.resolved` changed | 3 |
| Any `Project.swift`, `Workspace.swift`, or helper changed | 5 |
| Source-only change | none — Xcode handles it |

## Common failure modes

- **`tuist: command not found`** after step 1 → shell activation missing. Confirm `eval "$(mise activate zsh)"` is in `~/.zshrc` and that the terminal was reopened.
- **`tuist version` reports the brew-installed version, not the pinned one** → mise activation is loaded but `mise trust` was never run, or the user is in a directory outside the repo.
- **`tuist generate` errors with "package not resolved"** → step 3 was skipped. Run `tuist install`.
- **Build succeeds but SwiftLint warning says binary not found** → step 3 was skipped or `Tuist/.build` was wiped. Run `tuist install`.
- **`tuist generate` does not print "Using cache binaries"** → step 4 was skipped or the cache is corrupted. Re-run `tuist cache --cache-profile only-external`.
- **`mise` warning "config files are not trusted"** → run `mise trust` once.

## Non-goals

This skill does **not** handle:

- Installing Homebrew itself (assume present on macOS dev machines).
- Installing Xcode or the iOS simulators.
- Provisioning profiles or code signing identities.
- CI-specific configuration beyond the four bootstrap steps above.
